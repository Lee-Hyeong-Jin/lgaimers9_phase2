## 5. Target / label / training 감사
- 주 타깃 4클래스: 학습 행의 `asof_*` 누적 비율과 **같은 투수의 다음 행** 누적 비율의 차분으로 (성공/역방향/가운데/기타) 복원(`_recover_indicators`), 마지막 행은 자기 `control_success`와 조건부 기대값으로 보정. 보조 타깃(볼/스트라이크/기타, 구종군)도 같은 방식. **train 내부의 미래 행만** 사용 → FAQ 08-10 #6·08-19 #21 "학습 데이터 내 제약 없음", 08-20 #27 aux head 허용에 해당. 추론에서는 이 함수가 dead code(도달 불가)이며 test에는 정답 컬럼이 없어 실행될 수도 없다(FAQ 08-19 #22의 금지 사례는 test 측).

- TRAIN에서 허용된 구조를 TEST에 적용한 곳: 없음(추론은 행 + train 통계만).

- AMBIGUOUS(lg_shift): 코드 수정으로 해소되는 문제가 아님. 선택지 ① 현 상태 유지 + 소명(권고: #25가 동일 유형을 허용 범위로 답함), ② 보수적 대안 = `lg_shift`를 학습 근거만으로 정한 값으로 되돌린 제출(예: fold-2024 잔차 기반 0.010~0.016 중 학습 문서화 값)… 다만 이미 제출된 v40/v41/v48/v59 이력은 삭제할 수 없으므로(재안내 5항) 새 제출로 이력이 사라지지는 않는다 → ①을 택하고 이력을 투명하게 소명한다.

### 최종 판정
근거: CRITICAL·HIGH RISK 0건. 핵심 lineage와 test-row independence를 파일 단위·중간값 단위·클린룸에서 실행으로 검증했고, 실제 제출 아티팩트의 내용물을 직접 조사했으며, 클린 학습 재현이 일반적 오차 범위 안에서 성공했다. 남은 AMBIGUOUS 1건(`lg_shift` 결정 방식)은 v59 코드의 문제가 아니라 이미 존재하는 제출 이력에 대한 운영진의 "정도" 판단 사항이며, 운영진의 기존 답변(#12, #25)이 같은 유형을 허용 범위로 밝힌 바 있어 소명 자료를 첨부하는 조건으로 제출 상태를 유지한다.
